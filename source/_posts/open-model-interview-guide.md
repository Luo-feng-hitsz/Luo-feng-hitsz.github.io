### 面试时先说这五句

- Kimi K3 把线性递归注意力、周期性全局注意力和深度方向的残差检索组合起来，重点是 1M 上下文、多模态与大规模稀疏 MoE 的共同效率。

- DeepSeek V4 先压缩 Token，再在压缩表示上做稀疏或稠密注意力，并用 mHC 稳住超深残差信号，追求极低的 1M 推理成本。

- Qwen3.5 的主线是 3:1 的 Gated DeltaNet 与全注意力混合、原生视觉语言早融合、多语言和可切换思考模式。

- GLM-5.2 的关键是 IndexShare：多层稀疏注意力共享一次索引，配合长程 Agent RL 与上下文压缩。

- MiniMax M3 用按 GQA 组选择 Top-16 块的 MSA，把百万上下文注意力变成更规则、GPU 友好的块稀疏计算。

| **共同趋势** | **主要分歧** |
| --- | --- |
| 稀疏 MoE 扩容量 | 专家数量、Top-k、共享专家与通信方案不同 |
| 百万级上下文 | 递归状态、压缩检索、Token 稀疏与块稀疏不同 |
| 能力专家化后训练 | GRPO/PPO、OPD、推理档位与 Agent 环境不同 |
| 训练—系统共设计 | QAT、MTP、缓存、索引复用和专用内核侧重点不同 |

> **最重要的边界**  “开放权重”不等于 OSI 意义上的“开源”。Kimi K3 与 MiniMax M3 使用自定义许可证；商用、MaaS、品牌露出和营收门槛需要单独复核。



## 核心概念 ①：MoE、计算量与系统代价

### 为什么总参数很大，但每个 Token 没有把全部参数跑一遍

Mixture-of-Experts（MoE）把前馈网络分成大量专家。Router 为每个 Token 只选择 Top-k 专家，因此模型可以增加容量而不线性增加每 Token 的前向计算。总参数更接近“可容纳多少知识/专长”，激活参数更接近“这一 Token 实际走了多少计算”。

*图 2｜MoE 的真正取舍：容量、计算、通信与部署*

### 面试追问：MoE 真正难在哪

| **问题** | **为什么发生** | **典型处理** |
| --- | --- | --- |
| 负载不均 | Router 容易偏爱少数专家 | 负载均衡损失、容量限制、Kimi 的 Quantile Balancing |
| 跨卡通信 | 不同 Token 被送往不同 GPU 专家 | Expert Parallel、All-to-All 优化、通信计算重叠 |
| 小批量吞吐 | 专家被打散，算子尺寸变小 | 专家合并、连续批处理、路由缓存 |
| 权重显存 | 激活少，但完整专家仍需存储 | 分片、量化、分层缓存、按需加载 |
| 路由抖动 | 相似 Token 可能走不同专家 | 更稳的路由训练、共享专家、蒸馏 |

**一句话回答：**MoE 省的是每 Token 计算，不自动省总权重显存和跨卡通信；实际吞吐取决于路由均衡、专家并行、批量大小与量化。



## 核心概念 ②：百万上下文不是“把窗口改成 1M”

{% asset_img figure-04.png "图 4" %}

*图 3｜五种旗舰模型的长上下文技术路线*

### 四层问题同时存在

| **层** | **核心问题** | **判断问题** |
| --- | --- | --- |
| 架构 | 如何避免 O(n²) 注意力与 O(n) KV cache 爆炸 | 线性递归、稀疏检索、压缩、滑窗还是混合？ |
| 训练 | 模型是否见过足够长、需要跨段整合的信息 | 原生训练长度如何增长？是否有长程合成任务？ |
| 系统 | 预填充、解码、缓存与并行如何落地 | KV/状态怎么存？索引能否复用？内核是否规则？ |
| 评测 | “能接收”不等于“能利用” | 真实长程 Agent、信息检索、跨文档推理是否稳定？ |

### 四类主路线

- 线性递归状态：KDA、DeltaNet。成本随序列线性增长，但把历史压进固定状态，存在信息损失。

- 压缩后检索：DeepSeek V4。先把多个 Token 压缩成条目，再 Top-k 或稠密访问压缩条目。

- Token/块稀疏：GLM DSA、MiniMax MSA。先用轻量索引器找候选，再只对候选做精确注意力。

- 周期性全注意力：Kimi、Qwen。用少量全注意力层补回全局精细交互，换取更稳的能力。

**边界：**Qwen3.5-397B 的官方模型卡列出 262,144 原生上下文；通过 YaRN 等配置可外推到约 1,010,000。Kimi K3、DeepSeek V4、GLM-5.2 和 MiniMax M3 的公开口径是 1M 原生支持。二者不能只看同一个“1M”标签。



## 核心概念 ③：后训练、蒸馏、量化与推理档位

{% asset_img figure-05.png "图 5" %}

*图 4｜同代旗舰的共同训练范式*

### 关键术语

| **术语** | **一句话解释** | **面试要点** |
| --- | --- | --- |
| SFT | 用高质量示范教会格式、工具协议和基本轨迹 | 可用性强，但能力上限受示范覆盖限制 |
| RL / GRPO / PPO | 用可验证奖励或评价器强化成功轨迹 | 环境、奖励和防作弊比算法名更关键 |
| OPD | 学生在自己的轨迹上对齐教师分布 | 减少分布偏移，适合融合多个专家教师 |
| QAT | 训练时模拟低精度误差 | 让部署精度和训练分布一致，优于事后量化 |
| MTP | 一次预测多个未来 Token | 既可作为训练辅助，也可加速推理解码 |
| 推理档位 | 允许不思考、高思考、最大努力等模式 | 在延迟、成本和解题能力之间做显式预算 |



### 为什么多教师 OPD 成为共同趋势

大模型后训练正在把不同能力拆成多个专家策略：推理、代码、Agent、搜索、办公环境等。直接合并权重容易互相干扰；只蒸馏教师生成的数据又会遇到学生分布偏移。OPD 让学生自己采样轨迹，再让多个教师在这些状态上提供全词表分布，因而更容易把专长统一回一个模型。

> **面试表达**  SFT 解决“会不会按要求做”，RL 解决“能不能在可验证环境里做成”，OPD 解决“多个专长如何统一”，QAT/MTP 解决“部署时能否低成本跑起来”。

| **常见误区** | **更准确的理解** |
| --- | --- |
| SFT 能替代 RL | SFT 学示范分布；RL 还要在环境中探索并优化可验证结果。 |
| OPD 等于权重合并 | OPD 对齐的是教师在学生轨迹上的概率分布，不是直接平均模型权重。 |
| QAT 只是压缩文件 | QAT 在训练中暴露量化误差，目标是保持低精度执行时的能力与稳定性。 |
| MTP 一次输出就必然加速 | 只有高接受率、低验证开销和匹配的推理内核共同成立，才会兑现吞吐收益。 |



> **Kimi K3**  
> **把线性递归、全局注意力、深度检索和超大 MoE 组合在一起**

## Kimi K3：架构总览

> **30 秒定位**  Kimi K3 是 2.8T 总参数、104B 激活参数的原生多模态 MoE。它用 69 层 KDA 与 24 层 Gated MLA 形成约 3:1 混合，把序列方向的线性效率和周期性全局交互结合；再用 AttnRes 改善深度方向的信息流。

| **项目** | **公开规格** | **为什么重要** |
| --- | --- | --- |
| 规模 | 2.8T 总参数；104B 激活 | 容量极大，但每 Token 只走少量专家 |
| 深度 | 93 层：69 KDA + 24 Gated MLA | 约 3:1 的线性/全注意力混合 |
| MoE | 896 路由专家；16 激活 + 2 共享 | 细粒度专长；路由和通信挑战巨大 |
| 上下文 | 1M | 需要架构、训练与 Agent 系统共同支持 |
| 模态 | 文本、图像、视频；MoonViT-V2 约 401M | 从预训练开始混合视觉，而非后外挂编码器 |
| 精度 | SFT 起加入 MXFP4 权重 / MXFP8 激活 QAT | 面向低精度部署 |

### 四个最值得记住的创新

- KDA：带逐通道遗忘门的线性递归状态；长序列成本线性，但压缩历史可能损失精细 Token 交互。

- Gated MLA：周期性补回全局内容交互；K3 不依赖显式位置编码，把时序更多交给门控状态与注意力结构。

- AttnRes：沿深度方向检索更早层输出，而非只走相邻残差链，使深层更容易取回中层表征。

- Stable LatentMoE：把路由表示压到约 3584 维，并用 SiTU-GLU 抑制离群值，稳定 896 专家训练。

## Kimi K3：训练、系统与面试追问

### 预训练与长上下文

- 从预训练开始联合文本与大规模视觉数据，避免视觉能力只在后期对齐。

- 常规预训练长度从 8K 逐步到 64K；Cooldown 阶段再从 256K 扩展到 1M。

- 长上下文合成任务要求模型整合分散在不同位置的信息，而不是只做局部 needle 检索。

- 官方报告给出相对 K2 约 2.5× 的 scaling efficiency 口径；这是同家族官方实验，不应横向当作绝对榜单。

### 后训练：九个专家策略如何合并

K3 将通用、通用 Agent、代码三个领域分别训练 low/high/max 三种努力档位，共九个专家策略；最终通过 Multi-Teacher On-Policy Distillation 统一。Agent 侧还采用部分 rollout、Agentic GRM 与可恢复环境，降低长轨迹训练成本。

| **阶段** | **上下文 / 策略** | **目的** |
| --- | --- | --- |
| 预训练 | 8K → 64K | 先学稳定的通用与原生多模态能力 |
| Cooldown | 256K → 1M | 集中强化跨段整合与百万上下文 |
| 后训练 | 9 策略 → 多教师 OPD | 把领域和努力档位合回单一可部署模型 |



### 系统协同

| **组件** | **作用** | **面试落点** |
| --- | --- | --- |
| MoonEP | 平衡专家并行与 All-to-All | 大 MoE 的瓶颈常是通信，而非 FLOPs |
| KDA Kernel / CP | 优化递归状态并行 | 线性注意力需要专用算子才能兑现理论优势 |
| AgentENV | 可恢复 microVM 环境 | 长 Agent rollout 失败可续跑，降低浪费 |
| 外部 KV / 前缀缓存 | 缓存全注意力与 Agent 前缀 | 混合 KDA 需要专门的前缀复用策略 |

#### 面试官：KDA 已经线性了，为什么还保留 MLA？

**30 秒回答：**

线性递归状态把历史压进固定容量，适合吞吐和超长序列，但会牺牲任意 Token 间的精细内容交互。周期性 Gated MLA 相当于全局校正层，补回检索和复杂关联能力。

**追问展开：**

真正的取舍不是“线性一定优于全注意力”，而是用 3:1 混合把大部分层的成本降下来，再把稀缺的 O(n²) 预算花在最有价值的全局交互上。

> **风险与边界**  2.8T 权重仍带来极高的存储与集群门槛；896 专家让路由与通信复杂。Kimi K3 License 不是 MIT/Apache，MaaS 与大规模商业使用需复核专门条款。

## DeepSeek V4：Pro 与 Flash

> **30 秒定位**  DeepSeek V4 的核心不是单一稀疏注意力，而是 CSA、HCA、局部窗口和 mHC 的组合。Pro 追求能力上限，Flash 追求更低激活量；两者都原生支持 1M 文本上下文，并以极低 KV 与单 Token FLOPs 为重点。

| **版本** | **总参 / 激活** | **层数与专家** | **1M 公开效率口径** |
| --- | --- | --- | --- |
| V4-Pro | 1.6T / 49B | 61 层；384 路由专家，6 激活 + 1 共享 | 相对 V3.2：单 Token FLOPs 27%，KV 10% |
| V4-Flash | 284B / 13B | 同一技术家族的轻量型号 | 相对 V3.2：单 Token FLOPs 10%，KV 7% |

以上效率均是官方报告同口径声明，不能直接与其他厂商不同硬件/实现的吞吐数字混排。[S3][S4]

### CSA 与 HCA 怎么分工

| **机制** | **做法** | **优势** | **代价** |
| --- | --- | --- | --- |
| CSA | 每 m 个 Token 压成条目；在条目上 Top-k；保留局部滑窗 | 全局检索稀疏、局部信息不丢 | 需要训练索引器，可能漏召回 |
| HCA | 用更大的 m′ 强压缩，再对压缩条目做稠密注意力 | 以很少条目保留全局概况 | 细节更依赖其他分支补偿 |

### mHC：不是另一种注意力

mHC（manifold-constrained Hyper-Connections）作用在残差流。它把残差宽度扩展 4 倍，并用 Sinkhorn 把混合矩阵约束为双随机矩阵，使信号在多分支、多层之间传播时不容易爆炸或塌缩。CSA/HCA 解决序列长度，mHC 解决网络深度与多分支稳定性。



## DeepSeek V4：训练稳定性、OPD 与部署

### 超大规模预训练

- Flash 训练约 32T Token，Pro 约 33T Token；上下文训练按 4K → 16K → 64K → 1M 递进。

- 稀疏注意力不是从第一步就完全启用，而是在稠密注意力 warm-up 后逐步接入，降低训练早期不稳定。

- 优化器采用 Muon 混合方案，对大矩阵方向用 Newton–Schulz 近似正交化更新；其他参数仍可使用常规优化器。

### 损失尖峰如何处理

| **机制** | **问题** | **处理** |
| --- | --- | --- |
| Anticipatory Routing | 专家路由在损失尖峰前出现异常 | 根据先兆动态调整路由，避免热点扩大 |
| SwiGLU Clamp | 大激活离群值导致数值不稳 | 线性部分裁剪到约 [-10, 10]，门控上界约 10 |
| 前 3 层 Hash MoE | 浅层路由噪声与训练成本 | 用确定性哈希路由替代学习型 Router |



### 后训练与持久思考

多个能力专家先用 SFT + GRPO 训练，再由超过 10 个教师通过全词表 OPD 统一；学生在自己的轨迹上最小化反向 KL。工具场景支持跨工具调用、甚至跨用户轮次保留思考状态，重点是长程任务连续性，而不是每次调用后“失忆”。

### MXFP4 QAT

V4 针对专家权重和 CSA 索引器的 Q/K 路径做低精度训练，让长上下文部署的权重带宽与索引成本进一步下降。面试时应把 QAT 说成“训练分布内的量化噪声适配”，而非简单压缩文件大小。

#### 面试官：CSA 与普通稀疏注意力有什么不同？

**30 秒回答：**

CSA 不是直接在原始 Token 上 Top-k，而是先把多个 Token 压成条目，再检索压缩条目；同时用局部滑窗保留块内细节。因此它同时降低索引规模和 KV 存储。

**追问展开：**

对比 GLM 的 DSA 与 MiniMax 的 MSA：前者偏 Token 级候选，后者偏块级候选；CSA 先改变表示粒度再稀疏，HCA 则更激进地压缩后做稠密访问。

> **风险与边界**  当前开放旗舰是文本模型；技术报告把多模态列为未来方向。压缩和稀疏检索会引入召回风险，因此 1M 接入能力必须用真实长程任务验证。

> **3× Gated DeltaNet + 1× 全注意力；原生视觉语言早融合**

## Qwen3.5-397B-A17B：最新旗舰规格

> **30 秒定位**  Qwen3.5-397B-A17B 是 397B 总参数、17B 激活参数的原生视觉语言 MoE。60 层按 15 个重复组组织，每组 3 层 Gated DeltaNet 后接 1 层 Gated 全注意力，兼顾线性长序列效率和周期性全局交互。

| **项目** | **官方模型卡** | **面试含义** |
| --- | --- | --- |
| 规模 | 397B 总参数；17B 激活 | 五者中激活参数较小，强调单位 Token 效率 |
| 深度 | 60 层；15×(3 DeltaNet + 1 Full Attention) | 3:1 混合结构与 Kimi 思路相似，具体机制不同 |
| MoE | 512 专家；10 路由 + 1 共享 | 专家数大、每 Token 激活比例低 |
| 上下文 | 262,144 原生；YaRN 可到 1,010,000 | 必须区分训练窗口与位置外推 |
| 模态 | 文本、图像、视频早融合 | 视觉 Token 进入统一主干，不是仅拼接描述 |
| 语言 | 201 种语言和方言 | 多语言覆盖是 Qwen 系列长期优势 |
| 许可 | Apache-2.0 | 商用与二次开发边界最清晰的一类 |

### DeltaNet 为什么要和全注意力混合

Gated DeltaNet 通过递归状态线性处理序列，适合长上下文与流式推理；但固定状态不容易无损保留任意远距离细节。每四层一次 Gated Full Attention 提供全局精细检索。与 Kimi K3 的共同点是“多数线性层 + 少数全注意力层”，差别在于递归更新、门控、视觉融合和深度残差方案。

> **GLM-5.2**  
> **共享稀疏索引，把百万上下文成本和长程 Agent 训练一起优化**

## GLM-5.2：IndexShare 与长程 Agent

> **30 秒定位**  GLM-5.2 是 1M 文本上下文的超大 MoE，延续 GLM-5 的 DSA、MLA、Muon 与异步 RL，并新增 IndexShare：每 4 层只计算一次稀疏 Top-k 索引，其余层复用，官方给出 1M 下索引器每 Token FLOPs 约降低 2.9×。

| **项目** | **公开信息** | **边界** |
| --- | --- | --- |
| 规模 | 公开元数据约 753B；GLM-5 报告为 744B / 40B 激活 | 5.2 激活参数未单列，≈40B 仅为家族推断 |
| 深度 / MoE | 78 层；256 路由专家，8 激活 + 1 共享；前 3 层稠密 | 来自 5.2 公开配置 |
| 注意力 | DSA；约每 4 层一个索引器；索引 Top-k 约 2048 | IndexShare 复用候选集合 |
| 上下文 | 1M 原生 | 面向长代码库、研究与 Agent 轨迹 |
| 许可 | MIT | 开放权重商用边界清晰 |

### IndexShare 为什么有效

相邻层往往关注相似的远程 Token。若每层都重新运行稀疏索引器，二次检索成本会显著累积。IndexShare 用一个“lightning indexer”的候选 Top-k 服务后续数层，减少重复检索；主注意力仍对选中项做精确计算。代价是不同层的最优候选可能不完全一致。



### MTP 的系统共设计

- IndexShare：多层复用稀疏候选。

- KVShare：多步预测模块共享部分缓存，减少显存和访存。

- Rejection Sampling：验证候选 Token，保证输出分布正确。

- 端到端 Total Variation Loss：提升多 Token 提议质量；官方报告接受长度约提升 20%。

这四项不是彼此独立：IndexShare 降低候选检索，KVShare 降低多步预测缓存，拒绝采样保证最终分布，TV Loss 提高提议质量。最终收益取决于平均接受长度能否覆盖额外预测模块的计算。

> **面试抓手**  MTP 不是“无条件一次生成很多 Token”；它是先并行提议，再验证接受。接受率、共享缓存与验证内核共同决定真实加速。

来源：[S9][S10][S11]

## GLM-5.2：长程 RL、上下文压缩与防奖励黑客

### 为什么从 GRPO 转向 critic-based PPO

长程 Agent 任务的奖励延迟更长、轨迹更复杂，仅依赖组内相对奖励的方差可能很大。GLM-5.2 在长程场景使用带 Critic 的 PPO，并配合 Token 级 advantage，把信用分配更细地传播到工具调用和关键决策。

### Compaction：长轨迹不能无限堆历史

当 Agent 轨迹接近上下文上限时，系统将较早的对话、观察和中间结果压缩成摘要或结构化状态，再继续 rollout。它让 1M 窗口成为可管理的工作记忆，而不是一次性静态输入。

### 防奖励黑客

| **风险** | **处理** | **为什么重要** |
| --- | --- | --- |
| 伪造工具结果 | 规则过滤 + LLM Judge 检测可疑调用 | Agent 可能通过输出看似成功的字符串骗奖励 |
| 绕过任务约束 | 阻断可疑工具调用，但不中止整条 rollout | 保留后续学习信号，减少样本浪费 |
| 长轨迹错误累积 | Critic + Token 级 advantage + compaction | 把奖励更准确地分配给关键步骤 |

### 训练系统 slime

官方披露使用 slime 支持并行 OPD，让超过 10 个专家教师同时为学生提供分布，约两天完成统一阶段。面试重点不是记框架名，而是说明“长程 Agent RL 必须把环境、并发、容错、蒸馏和防作弊一起设计”。

#### 面试官：IndexShare 会不会损失每层的注意力多样性？

**30 秒回答：**

会有潜在损失，因为多层共享同一候选集合；收益是大幅降低重复索引成本。合理前提是相邻层远程注意力候选高度相关，且主分支仍对候选做层独立的精确注意力。

**追问展开：**

可从共享跨度、Top-k 大小、召回率、长程任务消融与 GPU 实际吞吐评估。如果模型需要非常不同的层级检索，共享跨度就不能过大。

> **按 GQA 组检索 Top-16 块，把稀疏性变成规则 GPU 工作负载**

## MiniMax M3：MSA 块稀疏注意力

> **30 秒定位**  MiniMax M3 是约 428B 总参数、23B 激活参数、1M 原生多模态 MoE。其 MSA 用超轻索引分支按 GQA 组选择 Top-16 个 128-Token 块，主分支只对这些块做精确 Softmax，目标是让百万上下文检索既稀疏又适合 GPU。

| **项目** | **公开规格** | **面试含义** |
| --- | --- | --- |
| 规模 | ≈428B / ≈23B；60 层 | 中等激活规模，强调推理效率 |
| MoE | 128 专家；4 路由 + 1 共享；前 3 层稠密 | 每 Token 专家较少，通信相对可控 |
| MSA | 块大小 128；每 GQA 组 Top-16 块；始终保留局部块 | 最多约 2048 个远程 Token 候选/组 |
| 上下文 / 模态 | 1M；文本、图像、视频 | 原生多模态长上下文 |
| MTP | 7 个预测模块 | 为多 Token 并行解码服务 |
| 推理模式 | enabled / adaptive / disabled | 在能力、时延、成本间切换 |

### MSA 的两条分支

| **分支** | **做什么** | **训练信号** |
| --- | --- | --- |
| Index Branch | 每个 GQA 组一个索引 Q、共享索引 K；分数 max-pool 到块；选 Top-16 | 用 KL 对齐该组主注意力的平均分布 |
| Main Branch | 仅对选中块和本地块做精确 GQA Softmax | 主分支梯度在索引对齐目标中 stop-gradient |



## MiniMax M3：效率口径、训练证据与边界

### 为什么按块、按 GQA 组

Token 级随机稀疏容易产生不规则访存。固定块让 GPU 可以批量加载连续 KV；按 GQA 组共享候选又减少索引开销，同时允许不同头组关注不同区域。它用少量召回精度换取显著更可实现的内核效率。

### 官方效率数字应该怎么引用

| **来源** | **实验对象** | **公开口径** | **正确说法** |
| --- | --- | --- | --- |
| MSA 论文 | 109B MoE，3T Token 原生多模态训练 | 1M 理论计算约降 28.4×；H800 prefill 14.2×、decode 7.6× | 证明 MSA 路线与内核共设计的可行性 |
| M3 模型卡 | M3 相对 M2 | prefill 9×、decode 15×；每 Token 计算约 1/20 | 是同公司版本对比，不等同跨模型绝对速度 |

### KL 对齐为什么有用

Top-k 选择不可微，索引分支若只靠最终语言建模损失很难学到召回。MSA 用主注意力分布作为软目标，让轻量索引器学习“哪些块值得精确计算”；主分支停止梯度，避免为迎合索引器而改变注意力。



### 与 GLM DSA 的区别

- 粒度：MSA 选择块；DSA 更接近 Token 或候选位置级稀疏。

- 共享方式：MSA 在 GQA 组内共享块候选；GLM-5.2 在深度方向跨数层共享索引。

- 硬件取向：MSA 的块连续性更强，容易实现高效访存；Token 级 DSA 召回更细。

### MSA 面试白板五步

| **步骤** | **数据流** | **要点** |
| --- | --- | --- |
| 1 | 每个 GQA 组产生索引 Q，共享索引 K | 控制索引开销 |
| 2 | Token 分数 max-pool 到 128-Token 块 | 把不规则稀疏变成连续访存 |
| 3 | 每组选择 Top-16 块并保留局部块 | 远程召回与局部稳健并存 |
| 4 | 主分支只在候选块内做精确 GQA Softmax | 稀疏的是候选，计算仍精确 |
| 5 | 用组平均主注意力做 KL 软目标 | 训练轻量索引器学会召回 |

#### 面试官：块稀疏会漏掉跨块的关键 Token 吗？

**30 秒回答：**

可能。MSA 通过轻量索引器、较大的 Top-16 候选、每组独立选择和始终保留局部块降低漏召回；再用主注意力 KL 蒸馏索引分布。

**追问展开：**

评估时不只看 perplexity，还要看跨文档检索、长代码依赖、视频长程定位与不同 Top-k/块大小的消融。块越大越适合硬件，但候选越粗。

- 训练—系统共设计：QAT、MTP、缓存复用、专用内核、可恢复 Agent 环境。

## 横向对比 ③：按场景选模型

| **场景** | **优先考察** | **原因** | **必须追加验证** |
| --- | --- | --- | --- |
| 超长代码库 Agent | GLM-5.2 / DeepSeek V4 / Kimi K3 | 原生 1M；强调长程工具与缓存 | 真实仓库成功率、compaction、工具状态 |
| 多模态研究/视频 | Kimi K3 / MiniMax M3 / Qwen3.5 | 开放旗舰支持图像与视频 | 视频 Token 成本、时间定位、跨模态长程 |
| 低激活部署 | Qwen3.5 / DeepSeek V4-Flash | 17B / 13B 激活口径 | 总权重显存、量化、吞吐和生态 |
| 许可清晰商用 | Qwen3.5 / DeepSeek V4 / GLM-5.2 | Apache-2.0 / MIT | 依赖组件和数据合规 |
| 极致稀疏注意力研究 | MiniMax M3 / GLM-5.2 / DeepSeek V4 | 块稀疏、Token 稀疏、压缩稀疏三路线 | 召回率、内核、硬件适配 |
| 超大 MoE 系统研究 | Kimi K3 | 896 专家与 2.8T 总参数 | EP、路由均衡、容错和成本 |

### 一个完整选型问题应该包含

- 任务：文本/视觉/视频？静态长文还是长程 Agent？准确率还是延迟优先？

- 负载：输入长度、输出长度、并发、批量大小、缓存复用率。

- 硬件：单机/多机、显存、互联、低精度支持、稀疏内核成熟度。

- 产品：工具协议、推理预算、可恢复状态、安全审计。

- 合规：模型许可证、训练数据声明、商用/MaaS/品牌条款。

> **不要用“谁 benchmark 第一”结束选型**  各家报告的模型版本、推理档位、工具、上下文、评测脚本和日期不同。面试中更可靠的做法是先统一 harness 与成本预算，再比较任务成功率、延迟、显存和稳定性。



## 高频面试问答 ①：架构与长上下文

#### 1. 为什么这些模型都采用 MoE？

**30 秒回答：**

MoE 允许总容量增长而每 Token 只激活少数专家，是把知识容量与前向计算解耦的主要手段。

**追问展开：**

但总权重显存、路由均衡和 All-to-All 通信不会消失。真正指标应包含激活参数、专家 Top-k、共享专家、批量大小和集群互联。

#### 2. 线性注意力是否已经解决长上下文？

**30 秒回答：**

没有。它把 O(n²) 交互压进固定状态，成本更低，但可能忘掉精细信息；还需要长程训练、全局校正层、系统状态管理与真实任务评测。

**追问展开：**

Kimi 用 KDA + MLA，Qwen 用 DeltaNet + Full Attention，正说明纯线性状态通常需要周期性全局交互补偿。

#### 3. KDA、DeltaNet、DSA、MSA 的根本区别？

**30 秒回答：**

KDA/DeltaNet 是递归状态型；DSA 是先索引候选 Token 再精确注意；MSA 是按块、按 GQA 组索引候选，再在块内精确注意。

**追问展开：**

比较维度包括状态容量、检索粒度、召回风险、KV 成本、内核规则性与是否需要周期性全注意力。

#### 4. DeepSeek V4 为什么同时有 CSA 和 HCA？

**30 秒回答：**

CSA 用中等压缩 + Top-k 处理选择性全局检索，HCA 用强压缩 + 稠密访问保留全局概况；局部窗口负责块内细节。

**追问展开：**

三者分别覆盖“找关键远程信息、看全局摘要、保局部精度”，比单一稀疏机制更稳。

#### 5. 原生 1M 和外推 1M 有何不同？

**30 秒回答：**

原生 1M 通常意味着训练流程、架构和系统都以该长度适配；外推 1M 主要通过位置缩放让模型接收更长输入，真实利用能力需额外验证。

**追问展开：**

Qwen3.5 是 262K 原生、约 1.01M YaRN 外推。还应查长程任务、位置参数、预填充延迟与状态/KV 成本。

## 高频面试问答 ②：训练与优化

#### 6. OPD 相比普通蒸馏好在哪里？

**30 秒回答：**

学生在自己的轨迹上采样，教师对这些状态给分布，能减轻只学习教师轨迹造成的 covariate shift。

**追问展开：**

多教师 OPD 还可以把代码、推理、Agent 等专家统一到一个学生；通常使用全词表 KL，而不仅是最终答案。

#### 7. 为什么先 SFT 再 RL？

**30 秒回答：**

SFT 提供稳定格式、工具协议和可用初始策略；RL 再把模型推向可验证成功。如果直接 RL，探索空间太大、奖励容易被钻空子。

**追问展开：**

长程 Agent 还需要环境容错、部分 rollout、compaction、Critic、规则与 LLM Judge 等基础设施。

#### 8. Muon 为什么在这些报告里频繁出现？

**30 秒回答：**

Muon 对二维权重更新做近似正交化，改善大矩阵优化的尺度和方向条件，适合超大 Transformer/MoE 的高效训练。

**追问展开：**

通常与 AdamW 类优化器混合使用；Kimi 进一步做 Per-Head Muon，DeepSeek/GLM 也采用分参数路径。

#### 9. QAT 与 PTQ 的区别？

**30 秒回答：**

PTQ 在训练后量化；QAT 在训练时注入量化误差，让模型适应低精度。对 MXFP4 专家权重和稀疏索引这类敏感路径，QAT 通常更稳。

**追问展开：**

要看校准数据、权重/激活精度、累加精度、关键层保留精度与硬件支持，不能只报“4-bit”。

#### 10. MTP 为什么既能训练又能推理加速？

**30 秒回答：**

预测多个未来 Token 提供更密集的训练信号；推理时可一次提出多个候选，再用主模型或拒绝采样验证，减少串行解码步数。

**追问展开：**

有效加速取决于接受长度、额外模块成本、KV 共享和验证实现。GLM-5.2 把 IndexShare/KVShare 与 MTP 一起优化。

## 高频面试问答 ③：系统、评测与合规

#### 11. 为什么理论 FLOPs 降低不等于实际吞吐提高？

**30 秒回答：**

推理还受显存带宽、通信、索引、访存规则性、批量大小与内核效率限制。

**追问展开：**

MiniMax MSA 强调块连续性和共设计内核；Kimi 强调 MoonEP；GLM 强调索引复用，都是把算法稀疏转成硬件可兑现收益。

#### 12. 怎么公平比较五个模型？

**30 秒回答：**

固定模型版本、推理档位、量化、工具、prompt、context、并发、硬件和评测脚本，再同时报告成功率、延迟、显存和成本。

**追问展开：**

官方报告数字适合解释设计方向，不适合直接拼成跨厂商排行榜。尤其 Agent benchmark 很容易受工具脚手架与预算影响。

#### 13. 如何评价一个“1M 模型”的真实能力？

**30 秒回答：**

分开测接入、检索、跨段推理、状态保持、长程 Agent 与系统成本。

**追问展开：**

可用 passkey/needle 做底线，再用跨文档多跳、长代码依赖、时间序列视频问答和多小时工具轨迹；同时记录位置敏感性和 compaction 影响。

#### 14. 开放权重与开源有什么区别？

**30 秒回答：**

开放权重只说明可下载参数；真正开源还涉及许可证权利、训练代码/数据披露和 OSI 定义。不能把自定义社区许可证自动叫 Apache/MIT 式开源。

**追问展开：**

本手册中 DeepSeek V4、GLM-5.2 为 MIT，Qwen3.5 为 Apache-2.0；Kimi K3 与 MiniMax M3 有自定义商业条款。

#### 15. 如果只能记一个通用回答框架？

**30 秒回答：**

先定义模型解决的问题，再讲架构、训练、系统部署，最后补证据与边界。

**追问展开：**

也就是五层：问题定义 → 架构 → 后训练 → 系统与部署 → 证据与边界。这样不会陷入只背参数。

### 示范：用五层结构回答“DeepSeek V4 有什么创新？”

## 面试前速记卡

### 十句必须会说

- MoE 让总容量与每 Token 计算解耦，但权重显存和跨卡通信仍在。

- 百万上下文 = 架构 + 训练分布 + 缓存/系统 + 长程评测，缺一不可。

- Kimi K3：KDA + Gated MLA + AttnRes + 896 专家。

- DeepSeek V4：压缩条目上的 CSA/HCA + mHC + 多教师 OPD。

- Qwen3.5：3× DeltaNet + 1× 全注意力；397B/17B；262K 原生、约 1.01M 外推。

- GLM-5.2：DSA + 每四层共享索引；长程 PPO、compaction 与防奖励黑客。

- MiniMax M3：按 GQA 组 Top-16 个 128-Token 块，再做精确 Softmax。

- AttnRes 检索早期层输出；mHC 约束残差混合，二者都改善深度但机制不同。

- OPD 在学生自己的轨迹上蒸馏多个教师，减少分布偏移。

- 官方 benchmark 先统一版本、预算、工具与 harness，再做横向比较。

### 五个高风险易错点

| **错误说法** | **正确说法** |
| --- | --- |
| Qwen3.5 原生 1M | 262K 原生；约 1.01M 需要 YaRN 等外推 |
| DeepSeek V4 是多模态模型 | 当前公开旗舰为文本；多模态是报告中的未来方向 |
| GLM-5.2 明确是 753B/40B | 总参约 753B；40B 是 GLM-5 家族口径推断 |
| 开放权重都可以无条件商用 | 需逐一检查 MIT/Apache 与自定义许可证条款 |
| 稀疏注意力一定更快 | 实际速度取决于索引、访存、内核、批量与硬件 |

### 建议反问面试官

- 你们的长上下文主要是静态文档，还是需要跨工具调用持续数小时的 Agent 状态？

- 目前瓶颈是预填充、解码、KV 显存、跨卡通信，还是任务成功率？

- 对推理预算、可恢复状态和安全审计有什么产品级约束？

- 模型选型使用统一评测 harness 吗？是否同时记录延迟、显存与成本？

## 结束语：真正值得记住的是“取舍”

这一代开放权重旗舰没有统一答案：Kimi K3 用线性递归和超大 MoE 扩容量；DeepSeek V4 用压缩注意力与残差约束压成本；Qwen3.5 用混合 DeltaNet 和原生视觉语言拓宽通用性；GLM-5.2 用共享索引与长程 RL 打磨 Agent；MiniMax M3 用块稀疏和内核共设计兑现百万上下文效率。

面试中最有区分度的，不是把名词念全，而是能继续说出：这个机制省了什么、牺牲了什么、系统如何落地、证据是否可比。

> **最后一句**  先讲问题，再讲机制；先讲收益，再讲代价；最后给证据边界。
