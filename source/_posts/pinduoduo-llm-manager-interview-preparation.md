> 面试轮次：三面 / 主管面  
> 面试日期：2026-08-26  
> 资料检索日期：2026-08-25  
> 适用方向：大语言模型、多模态大模型、搜索推荐广告算法、TEMU 电商算法

## 0. 先看结论

**不要把主管面当成纯聊天面。**

公开面经显示，拼多多算法岗的三面、主管面或高管面仍可能包含现场编码、数学题或跨方向技术追问。主管通常集中判断以下能力：

1. 项目是否真实，是否真正承担了核心工作。
2. 能否解释技术选择，而不只是复述模型结构。
3. 面对陌生问题时，能否快速澄清、拆解和推理。
4. 能否把离线模型指标连接到线上业务价值。
5. 表达是否简洁、结论是否明确、沟通成本是否足够低。
6. 求职动机、稳定性和对工作节奏的预期是否匹配。

最值得记住的一句话：

> 主管想确认的不是“你背过多少知识点”，而是“把一个不确定的问题交给你，你能不能独立推进并拿到结果”。

## 1. 公开面经汇总

### 1.1 2024 年拼多多算法工程师 1-4 面

来源：[牛客网：拼多多算法工程师面经（1234 面）](https://www.nowcoder.com/discuss/668558312559915008)

岗位涉及多模态大模型和搜广推。三面在原帖中被标注为“高管面”，主要内容包括：

- 自我介绍和实习介绍。
- 逐个说明实习中各环节的工作。
- 追问本人在每个环节具体做了什么。
- 数据集构造细节。
- 训练过程中的注意事项。
- 使用的训练框架。
- 现场编码：重排链表。
- 反问。

重要信号：

- 三面仍有手撕代码。
- 项目追问从“整体介绍”继续深入到“每个环节的个人贡献”。
- 一面、二面、三面的面试官方向可能不同，大模型候选人也可能遇到搜广推面试官。

同一经历后来出现在知乎：[拼多多 2025 届秋招算法工程师](https://zhuanlan.zhihu.com/p/6945096309)。两篇对三面标签和时长的描述略有差异，因此应按同一个样本计算，题目内容比轮次标签更值得参考。

### 1.2 2024 年 TEMU 大模型算法岗

来源：[知乎：面了拼多多大模型算法岗，被疯狂拷打](https://zhuanlan.zhihu.com/p/705847442)

公开题目包括：

- 项目背景、要解决的问题及项目价值。
- 训练数据如何构造、数据类型、数据规模。
- 是否进行微调，为什么微调。
- Prompt Tuning、Adapter Tuning、LoRA 的原理和适用场景。
- 如何评估微调效果。
- GPU 规格和显存占用。
- 为什么选择 70B 基座模型。
- 模型训练和推理加速方法。
- 如何避免灾难性遗忘和“复读机”问题。
- 高质量微调数据的筛选方法。
- Transformer、RoPE、QKV、Self-Attention、Mask、BERT CLS。
- 现场编码：岛屿数量、电话号码字母组合。

可信度说明：该文带有社群推广内容，更像二次整理，适合用来补充题库，不应单独用它判断面试流程。

### 1.3 2025 年 TEMU 多模态大模型算法岗

来源：[知乎：拼多多多模态大模型算法工程师面试](https://zhuanlan.zhihu.com/p/32463510329)

方向为视觉语言大模型、商品分类、Visual Grounding、以图搜图和以文搜图。公开问题包括：

- 为什么从机器人、自动驾驶转向电商大模型。
- 职业规划，拼多多的吸引力。
- 是否理解并接受团队的工作节奏。
- 目标检测 Backbone 的设计考虑。
- RepVGG 量化问题及改进。
- 目标检测发展脉络、YOLO、RCNN、DETR。
- CLIP 原理、缺点和 Batch Size 对对比学习的影响。
- MoCo 如何扩大负样本规模。
- 标签分配、二分图匹配、Sinkhorn、NMS-free。
- SGD、Adam、Momentum、高斯牛顿法和 LM。
- 论文动机、方法和个人贡献。
- 现场编码：最大岛屿数、打家劫舍变形。

该经历说明：即使岗位名称是“大模型”，面试也可能重点考察视觉基础、对比学习、优化方法和论文研究能力，而不是只考 LLM 八股。

### 1.4 2021 年拼多多算法工程师 1-3 面和 HR 面

来源：[牛客网：拼多多算法工程师一二三面 + HR 面](https://ac.nowcoder.com/discuss/694735?page=2)

三面主要内容：

- 自我介绍和论文。
- 成绩、保研或考研经历。
- 一个跨方向的芯片测试题。
- 候选人请求换题后，改问概率和数学。
- 等概率随机数生成，以及由概率 `p`、`1-p` 的随机源构造随机数。
- 时间复杂度。

作者总结“基本没有八股，项目问得很细”。评论区还提到拼多多可能统一安排面试，因此 CV、NLP、推荐方向的候选人可能遇到不同方向的面试官。

### 1.5 2022 年主管面短面试

来源：[牛客网：拼多多三面（主管面）](https://www.nowcoder.com/discuss/353159408093962240)

流程约 22 分钟：

- 开场算法题：删除被其他区间包含的区间。
- 介绍项目，但面试官中途要求进一步缩短。
- 简短反问。

重要信号：主管可能明显控制时间。回答应先给结论和最强证据，不能先铺五分钟背景。

### 1.6 较早的深度学习算法岗经验

来源：[知乎：深度学习算法岗（拼多多）](https://zhuanlan.zhihu.com/p/110683289)

该样本发布时间较早，主要考查传统机器学习、项目和工程落地，包括 GBDT、随机森林、模型融合、ROC/AUC、广播机制等。对当前大模型岗位的流程参考价值有限，但“项目和落地优先于纯八股”的风格与近年面经基本一致。

## 2. 主管面最明显的五条规律

### 2.1 项目深挖是绝对主线

主管可能沿着一个项目连续追问：

- 项目解决了什么真实问题，为什么值得做？
- Baseline 是什么，主要瓶颈是什么？
- 数据从哪里来，规模多大，如何清洗、去重、去泄漏？
- 为什么选这个基座模型？为什么不是更小或更大的模型？
- 为什么选 SFT、LoRA、DPO 或其他方案？
- 哪些工作是本人完成的，哪些是同事完成的？
- 做过哪些失败实验，为什么失败？
- 指标提升是否稳定，是否做消融和显著性分析？
- 离线指标和线上指标是否一致？
- 如果算力、时延或标注预算减半，如何重做？

### 2.2 技术选择必须有比较和约束

不要只回答“我们用了 LoRA”“我们选择了 70B”。主管更可能继续问：

- 和 Full Fine-tuning、Adapter、Prompt Tuning 相比，为什么选 LoRA？
- 质量、显存、训练速度和部署成本之间如何权衡？
- 这个选择在哪些条件下会失效？
- 如果模型规模扩大十倍，方案是否还能工作？

推荐回答结构：

> 候选方案 -> 实际约束 -> 选择理由 -> 量化结果 -> 适用边界

### 2.3 主管面仍可能现场编码

公开三面和主管面中明确出现了链表、区间和概率问题。不能因为前两轮已经写过代码，就默认三面不会再写。

### 2.4 面试官可能跨方向提问

需要至少掌握以下搜广推基础：

- Recall、Hit Rate、MRR、NDCG、AUC。
- 召回、粗排、精排和重排的基本链路。
- Pointwise、Pairwise、Listwise 的区别。
- InfoNCE 和对比学习。
- 大模型如何进入搜索、推荐、广告和商品理解链路。
- 如何将模型指标连接到 CTR、CVR、GMV、收入、留存或用户体验。

### 2.5 动机和节奏匹配会被直接确认

近年的 TEMU 面经多次出现：

- 为什么选择拼多多？
- 为什么从原研究方向转向电商大模型？
- 拼多多最大的吸引力是什么？
- 职业规划是什么？
- 是否理解并接受较快的工作节奏？

回答要真实，不要承诺自己无法长期接受的条件。

## 3. 明天高概率问题清单

### 3.1 项目和研究

1. 用 90 秒介绍你最有代表性的项目。
2. 这个项目解决什么问题，为什么值得投入？
3. 项目最难的部分是什么，为什么难？
4. 数据集如何构造，如何保证数据质量？
5. 如何避免训练集和评测集污染？
6. 为什么选择这个基座模型和训练方法？
7. 你的个人贡献是什么？如果没有你，项目会有什么不同？
8. 最失败的一次实验是什么，如何定位原因？
9. 做了哪些消融实验？每项改动分别贡献多少？
10. 如果重新做一次，你会改哪三点？

### 3.2 大模型训练与微调

1. SFT 的数据配比、学习率、Batch Size、Warmup 和 Epoch 如何设置？
2. LoRA 的原理是什么？`r`、`alpha` 和目标模块如何选择？
3. LoRA、QLoRA、Full Fine-tuning、Adapter 和 Prompt Tuning 如何取舍？
4. 如何避免灾难性遗忘、复读和过拟合？
5. 如何筛选高质量 SFT 数据？
6. 如何做数据去重、难例挖掘和 Curriculum Learning？
7. 显存不足时有哪些训练优化方法？
8. FP16、BF16、Loss Scaling 的关系是什么？
9. ZeRO、FSDP、Gradient Checkpointing 和 Gradient Accumulation 分别解决什么问题？
10. 如何评估微调模型的能力提升和能力退化？

### 3.3 Transformer 和推理

1. 从输入 Token 到输出 Token，完整描述 Decoder-only Transformer 的计算过程。
2. Q、K、V 各自代表什么？为什么要除以 `sqrt(d_k)`？
3. RoPE 的核心思想是什么？如何外推长上下文？
4. Causal Mask 和 Padding Mask 有什么区别？
5. KV Cache 如何降低自回归推理开销？它的显存瓶颈是什么？
6. FlashAttention 为什么更快、更省显存？
7. 量化、Continuous Batching、PagedAttention、Speculative Decoding 分别适用于什么场景？
8. 如何同时优化首 Token 时延、单 Token 时延和吞吐？

### 3.4 评估和业务落地

1. 离线评估集如何构建，如何防止过拟合评测集？
2. 自动评估、LLM-as-a-Judge 和人工评估如何组合？
3. 如何评估事实性、幻觉、安全性和拒答能力？
4. 离线指标上涨但线上业务指标下降，如何排查？
5. 电商搜索、推荐和广告为什么需要大模型？
6. 如何设计从召回到精排的多阶段系统？
7. 如何评估质量收益是否值得额外的推理成本？
8. 上线后出现延迟抖动、脏结果或指标回退，如何止损和定位？

### 3.5 主管和行为问题

1. 为什么选择拼多多，而不是其他大模型团队？
2. 为什么选择这个岗位和业务方向？
3. 未来三年的职业规划是什么？
4. 如何理解高强度和结果导向？
5. 与同事或导师技术意见不一致时，如何推进？
6. 同时有多个高优先级任务时，如何排序？
7. 遇到信息不完整但必须快速决策时，会怎么做？
8. 讲一次你主动发现并解决问题的经历。
9. 讲一次失败或延期，以及如何承担责任。
10. 你希望主管如何评价你入职前三个月的表现？

## 5. 回答模板

### 5.1 90 秒项目介绍

建议严格按照下面的顺序：

1. **问题**：业务或研究场景是什么，痛点是什么。
2. **规模与约束**：数据量、模型规模、算力、时延或标注限制。
3. **职责**：本人负责的模块和决策。
4. **方案**：核心方法，以及为什么选择它。
5. **结果**：量化指标、消融、线上或下游效果。
6. **复盘**：失败尝试、适用边界和下一步。

可直接套用：

> 这个项目解决的是____问题。原方案的主要瓶颈是____，数据规模和资源约束是____。我主要负责____，对比了____和____后，因为____选择了____。最终在____指标上从____提升到____，同时把____控制在____。项目中最关键的失败是____，我通过____定位并修复。重新做一次，我会优先改进____。

### 5.2 为什么选择拼多多

回答要包含“业务、能力匹配、成长”，不要只说平台大或薪资高。

示例结构：

> 我关注拼多多大模型岗位，核心原因是电商搜索、推荐、广告和商品理解有大规模真实数据与明确业务闭环，模型效果能够快速通过用户行为和经营指标验证。我的____经历与岗位需要的数据构造、模型训练和评估落地比较匹配。我希望下一阶段不只优化离线指标，而是完整参与从数据、训练到线上验证的迭代，这也是这个岗位最吸引我的地方。

### 5.3 是否接受工作节奏

只在符合本人真实情况时使用：

> 我对团队节奏有基本了解，也认真评估过。我能接受目标明确、反馈快速、结果导向的工作方式。对我来说，关键是能够理解优先级、对结果负责，并持续提升交付效率。我也希望进一步了解团队日常迭代节奏和紧急事项的管理方式。

不要为了过面试承诺自己无法长期接受的安排。

### 5.4 遇到不会的问题

推荐过程：

1. 复述问题，确认输入、输出和约束。
2. 明确自己知道什么、不确定什么。
3. 先给可工作的 Baseline。
4. 分析瓶颈，再逐步优化。
5. 给出验证方案和失败时的回退方案。

可使用的表达：

> 这个细节我没有直接实践过。我先基于已知条件做几个假设，并给出一个可验证的方案。如果假设不成立，我会再从____方向调整。

这比编造结论更能体现主管面需要的判断力。

## 6. 反问主管

优先选择两到三个：

1. 团队未来半年最重要的大模型业务目标是什么？
2. 这个岗位的离线评估指标与最终业务指标如何衔接？
3. 新人前三个月最希望交付什么结果？
4. 当前团队最大的瓶颈更偏数据、模型、评估还是工程效率？
5. 算法同学需要承担多少训练和推理 Infra 工作？
6. 您认为这个岗位表现优秀的人，最重要的共同特征是什么？
7. 如果我加入，您认为我当前背景与团队需求之间最大的差距是什么？

不建议在主管面只问：

- 官网可以直接查到的信息。
- “公司有什么培训”。
- 只问加班时间而完全不问工作内容。
- 过于宽泛的“团队做什么”。

薪资、假期和具体合同问题通常留给 HR 更合适。

## 7. 面试前冲刺安排

### 第一阶段：项目压力测试

对简历中的每个核心项目，准备以下六项：

- 数据。
- 方案选择。
- 指标与消融。
- 失败和排障。
- 个人贡献。
- 成本、时延和业务价值。

至少让自己能够对最强项目连续回答 20 分钟。

### 第二阶段：大模型核心

重点复习：

- SFT、LoRA、QLoRA。
- 数据质量和灾难性遗忘。
- RoPE、KV Cache、FlashAttention。
- 显存优化和分布式训练。
- 评估体系、幻觉和业务指标。

更完整的技术复习资料：[大模型算法岗位面试准备手册](/2026/08/02/llm-algorithm-interview-guide/)

### 第三阶段：手撕代码

优先完成第 4.3 节的六道题。不要继续无目的扩展题库。

### 第四阶段：主管问题和反问

口述以下内容并录音回听：

- 90 秒自我介绍。
- 为什么拼多多。
- 最成功和最失败的项目经历。
- 冲突、压力和优先级管理。
- 两个反问。

## 8. 面试前 10 分钟检查表

- [ ] 90 秒自我介绍已经压缩到重点。
- [ ] 能清楚说出最强项目的业务目标和个人贡献。
- [ ] 项目中的所有数字、指标和数据规模前后一致。
- [ ] 能解释一个失败实验，而不是只讲成功结果。
- [ ] 能回答为什么选择当前模型和训练方案。
- [ ] 熟悉重排链表、岛屿、区间和双指针模板。
- [ ] 手撕代码时会主动说复杂度和边界。
- [ ] 准备了“为什么拼多多”和职业规划。
- [ ] 准备了两个有业务含量的反问。

## 9. 信息边界与可信度

- 面经是候选人的主观回忆，不能代表固定题库。
- “三面”“主管面”“高管面”“技术面”的叫法在不同批次中并不统一。
- 部分帖子是同一经历的跨平台复写，不能重复计数。
- TEMU、多多主站、搜索推荐广告和多模态团队的考查重点可能不同。
- 旧面经主要用于识别稳定风格，不应据此判断 2026 年的具体流程。
- 小红书网页搜索要求登录后查看结果，因此本文没有引用无法公开核验的小红书笔记。
- CSDN 搜索结果以转载和导流内容居多，未把无法确认原始出处的文章计为独立样本。

最后提醒：**先把自己的项目讲透，再扩展八股；先保证六道高相关代码题能独立写出，再刷新题。**
